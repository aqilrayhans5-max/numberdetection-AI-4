# DigitLab — Three-Digit Handwriting Detector

A responsive Flask web app that recognizes **exactly three handwritten digits** drawn directly on the webpage. There is no image-upload feature. The browser canvas sends a PNG to `/api/predict`; the Python backend preprocesses it and uses a PyTorch CNN + bidirectional LSTM + CTC sequence model.

## Important: train the model first

The ZIP contains the matching model architecture and training script, but does **not** contain trained weights. `multidigit_ctc.pth` must be generated by training before recognition can work. The site still opens without weights and `/api/health` explains that the model is missing.

## Run on Windows

1. Install Python 3.11.
2. Extract the ZIP to a simple folder such as `C:\\DigitLab-3Digit-App`.
3. Open that folder in File Explorer. Click the address bar, type `cmd`, and press Enter.
4. Run these commands one at a time:

```bat
py -3.11 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python train_3digit.py
```

The training script downloads MNIST on the first run, so internet access is required. Training may take several minutes or longer on a CPU. Keep the terminal open. It prints the validation **exact-sequence accuracy** each epoch and saves the best weights to `multidigit_ctc.pth`.

5. When training finishes, start the website:

```bat
python app.py
```

6. Open <http://127.0.0.1:5000>. Draw a number such as `123`, `407`, or `999`, then click **Recognize number**.
7. Check <http://127.0.0.1:5000/api/health>. It should show `"ok": true`.

## Deploy to Render

Before deploying, push these files to the root of the GitHub repository connected to your Render service:

- `app.py`
- `index.html`
- `train_3digit.py`
- `requirements.txt`
- `.python-version`
- **`multidigit_ctc.pth`**, generated by the training step

Do not upload `.venv/` or `data/`. Keep `multidigit_ctc.pth` in the same folder as `app.py`.

Render build command:

```bash
pip install -r requirements.txt
```

Render start command:

```bash
gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 2 --timeout 120
```

After deploy, check `https://YOUR-SERVICE.onrender.com/api/health`. The response must contain `"ok": true` before testing the drawing pad.

## Why this version returns three digits

The training set contains three-digit sequences only. The backend uses a CTC prefix beam decoder constrained to a sequence length of three instead of only using a greedy decoder that can collapse to one or two characters. The length constraint makes the output exactly three characters, but **does not guarantee the digits are correct**. Use validation exact-sequence accuracy to assess the trained model. Synthetic MNIST sequences do not cover every handwriting style; improve training data or collect examples if real-world accuracy remains low.

## Troubleshooting

- **“Model not trained”**: run `python train_3digit.py` and ensure `multidigit_ctc.pth` is next to `app.py`.
- **Health endpoint returns `ok: false` after deployment**: the model is missing or failed to load. Read Render logs and verify the `.pth` file was pushed.
- **It returns three digits but the value is wrong**: check the validation exact-sequence accuracy, draw larger and more separated digits, and retrain if needed. The fixed-length decoder cannot compensate for a poorly trained model.
- **Training download fails**: confirm internet access and rerun `python train_3digit.py`.
